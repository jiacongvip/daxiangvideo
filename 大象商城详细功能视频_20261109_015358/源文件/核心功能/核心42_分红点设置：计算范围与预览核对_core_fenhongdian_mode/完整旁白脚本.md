# 大象商城 · 分红点设置：计算范围与预览核对

## 先核对计算范围，再处理规则
这里是大象商城。后台维护分红点设置时，达标分红点是否参与计算，会改变计算使用的点数范围。这次从运营核对配置出发，说明两种模式、预览和历史记录的关系，只讲后台计算设置，不提供投入回报或收益保证。

## 在基础设置选择达标点是否参与
管理员在分红点设置的基础设置中，找到达标分红点参与计算选项。参与计算为默认模式，另一项是不参与计算。选择的是已经达到限额的点数是否纳入本次计算口径，不是新增商品、充值或创建新的会员账户。

## 总点数与剩余未达标点数分开
参与计算模式按会员总分红点数计算比例；不参与计算模式只按剩余未达标点数计算比例。相同会员的总点数与当前有效点数可能不同，运营要先明确使用哪一种口径，再核对预览，不把两种模式的结果放在一起比较成同一条规则。

## 预览确认模式，历史记录保留
手动预览可以显示当前计算模式，执行环节按所设置的模式处理，历史记录也可以回看对应模式。设置修改影响后续计算，不会重写已经执行的历史记录。运营可以先用预览核对范围，再对照历史记录区分原有结果与新口径。

## 模式、预览和历史三处对应
这次案例先确认达标点是否参与，再区分总点数与剩余未达标点数，最后通过预览和历史记录核对。大象商城分红点计算设置，让后台规则维护围绕明确口径展开，不把一个计算选项当成固定金额或实际到账承诺。
