# 大象商城｜会员升级申请资料与记录

## 1. 先把申请资料，配置清楚
角色：平台运营 / 申请会员
旁白：这里是大象商城。会员升级申请中，运营方要先决定收集哪些资料，会员再填写，后台再查看提交内容。这一条围绕申请资料与记录展开，把配置、填写和查看三个角色动作连接起来。
重点：配置资料；会员填写；后台查看
内部证据：core_升级资料表单汇报.md:9-19,35-43,68-70

## 2. 到对应等级，配置申请资料
角色：平台运营
旁白：运营人员在对应会员等级的申请升级设置中，开启申请并配置自定义资料。不同等级需要的内容可以不同，先明确申请人需要填写什么，再逐项安排字段名称与内容。
重点：选择对应等级；开启申请升级；配置资料字段
内部证据：core_升级资料表单汇报.md:11,35-43,86-91

## 3. 字段类型，按填写方式来选
角色：表单配置人员
旁白：文本字段可以安排填写提示。需要从预设项中选择时，使用单选、多选或下拉；需要日期或时间范围时，设置开始与结束内容。选项可以动态添加或删除，不把所有输入都塞进一个自由文本框。
重点：文本提示；单选 / 多选 / 下拉；日期 / 时间范围
内部证据：core_升级资料表单汇报.md:49-56

## 4. 必填项与选项，逐个设置
角色：表单配置人员
旁白：每个字段不只有一个标题，还要配置内容或选项，并明确是否必填。比如演示申请需要姓名、联系电话和一个选择项，就分别配置三个字段，而不是只写一句请提交资料。这里不使用真实申请人的个人信息。
重点：字段名称；内容或选项；必填设置
内部证据：core_升级资料表单汇报.md:25-29,49-56,88-90

## 5. 会员进入申请页，按字段填写
角色：申请会员
旁白：会员进入所申请等级的页面，按展示字段填写。文本项填写内容，选择项从已有选项中选择，再按要求提交。运营端负责配置清楚，会员端负责填写完整，两端围绕的是同一组申请资料。
重点：打开目标等级申请；查看配置字段；填写并提交
内部证据：core_升级资料表单汇报.md:11-19,78-82,88-91

## 6. 后台记录，按标签看内容
角色：后台运营
旁白：申请提交后，后台在会员等级申请记录中查看资料。字段标签与填写值要一一对应，方便知道某段内容属于姓名、联系方式还是选择项。运营人员查看的是这次提交的资料，不把资料展示本身当成自动升级结果。
重点：打开申请记录；查看资料列；字段标签与值对应
内部证据：core_升级资料表单汇报.md:41-43,68-70,88-91

## 7. 配置、填写、记录，连成一条线
角色：大象商城 · 申请资料管理
旁白：运营方配置字段与必填要求，会员按字段填写提交，后台按标签查看申请记录。把申请资料的来龙去脉讲清楚，后续业务人员才知道这次申请提交了什么。这就是会员升级申请资料管理的使用路径。
重点：字段配置；会员提交；后台记录
内部证据：以上各章节内部证据
